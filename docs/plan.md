# ねこ社員とフローチャート・アプリ設計

## 概要

iPad Safariで動く、インストール不要のWebアプリを制作する。小学校中学年以上が、ねこ社員の「おねがいごと」をかなえるため、正しいフローチャートを図形と矢印で組み立てる。自分で考える前に操作を学べるチュートリアルと、5つの独立ステージ型ゲームで構成する。

## 体験・画面設計

- 全画面の左上に会社ロゴを小さく固定表示する。ロゴ・社名・猫素材は後から差し替え可能にする。
- 起動画面（ホーム画面）の先頭に「あそびかた」カードを置き、その後に5ステージを表示する。どの問題も単独で開始・中断できる。各ステージを開く時は、記号の説明ポップアップを表示する。
- フローチャート編集画面では、開始・終了、処理、判断、くり返しの図形をドラッグ配置し、矢印で接続する。
- 「使う記号」には、各記号の役割に対応したフローチャート記号そのもの（開始・終了は角丸、処理は長方形、判断は菱形など）を表示する。
- 編集画面には記号の説明ボタンを置き、端子・処理・矢印の意味をいつでも再表示できるようにする。
- 接続可能な場所を強調表示し、配置・接続の操作を支援する。
- 「うごかす」操作で猫社員がフローチャートどおりに行動するアニメーションを再生し、成功または原因がわかる失敗表示を出す。
- 詰まった場合は猫が段階的なヒントを表示する。音は使わず、表情・吹き出し・アニメーションで達成感を演出する。
- 各ステージのクリア直後に簡素な「クリア！ おめでとう！」画面を表示し、その後は初期状態へ戻す。

## ステージ内容

### あそびかた（チュートリアル）

- ホーム画面では、最初のステージカードとして「あそびかた」と表示する。番号は付けず、ほかのステージよりも目立つ案内用カードにする。
- 目的は「1マスすすむ → おやつをひろう → おやつをたべる」の順に、記号の置き方・矢印のつなぎ方・実行方法を体験することとする。
- 盤面は1列3マスとし、ねこ社員は左端、おやつは中央に置く。右端は使わず、移動が1回で済むようにする。
- 開始・終了は最初から配置する。使える記号は「1マスすすむ」「おやつをひろう」「おやつをたべる」の3つだけにする。
- 正しいフローは「はじめ → 1マスすすむ → おやつをひろう → おやつをたべる → おわり」とする。おやつをたべた時点で成功とし、おわりまでつなぐ意味も体験させる。
- 利用者に順番を考えさせない。画面上に現在の1手だけを大きく表示し、対象の記号・接続端子・実行ボタンを順に強調する。
- 案内は次の順で進める。各操作が完了したら自動的に次の案内へ切り替える。
  1. 「『1マス すすむ』を、ここへドラッグしてね」
  2. 「はじめの ● から、『1マス すすむ』の ● へつないでね」
  3. 「『おやつを ひろう』を、ここへドラッグしてね」
  4. 「『1マス すすむ』から、『おやつを ひろう』へつないでね」
  5. 「『おやつを たべる』を、ここへドラッグしてね」
  6. 「『おやつを ひろう』から、『おやつを たべる』へつないでね」
  7. 「『おやつを たべる』から、おわりへつないでね」
  8. 「『うごかす』を おしてみよう」
- チュートリアル中に違う記号や接続を試した場合は、赤いエラーではなく「いまは ここを やってみよう」と表示し、次に必要な場所を再度強調する。
- クリア後は通常のクリア画面を表示し、「ホーム画面へ」から5ステージへ進める。

1. **おもちゃをとどけよう**：開始→処理→終了で、ねこ社員が拾ったおもちゃをヒト社員へ届ける手順を組み立て、順番に命令する基本を学ぶ。
2. **はこのなかみは？**：箱を開けるたびにランダムで決まる中身を確かめ、おもちゃならヒト社員へ届け、おやつなら食べる。判断図形の「はい／いいえ」で、状況に応じて動く。
3. **くりかえしをつかおう**：ループ処理の書き方を案内に沿って学ぶチュートリアルステージ。ねこ社員の前に3つ並んだおやつを、1マス進んで1つずつ食べる。「はじめ → ループ始端（3回くりかえす）→ 1マスすすむ → おやつをたべる → ループ終端（ここまでくりかえす）→ おわり」の形を組み立てる。ループ始端とループ終端はセットで使い、その間の処理を指定した回数だけ繰り返す。本物の反復端子の記号を用いる。
4. **ねこ社員の見回り**：同じ動きを繰り返すループを作る。
5. **おねがいごと大作戦**：処理・判断・くり返しを組み合わせ、猫社員の依頼を完成させる。

表示文はやさしい日本語にし、漢字は少なめ・必要なものにはふりがなを付ける。各ステージでは、完成後に本物のフローチャートとして「開始から終了まで到達できること」と、必要な分岐・ループが正しく接続されていることを判定する。

## 実装方針

- iPad横向きに最適化した、タッチ操作中心のレスポンシブWebアプリとして作る。
- ステージ定義、図形、接続、ヒント、正解条件をデータ化し、会社ロゴ・猫画像・会社紹介文を設定だけで置換できる構成にする。
- チュートリアル用ステージ定義には、正しい操作の順序、強調する対象、案内文を持たせる。通常ステージの実行ロジックを共有しつつ、チュートリアル時だけ案内順に操作を受け付ける。
- 利用者情報・スコア履歴は保存せず、画面内の進行状態だけを保持する。次の利用者に前の状態が残らないよう、ステージ完了時にリセットする。

## テスト計画

- iPad Safari相当のタッチ操作で、図形の配置・移動・矢印接続・削除が行えること。
- チュートリアルで、案内に沿って3つの記号の配置・4本の矢印接続・実行まで進めること。想定外の操作時は、次に必要な操作を再表示すること。
- 各5ステージで、正解フローは成功し、不足した接続・誤った分岐・不正なループは実行できないか理由付きで失敗すること。
- ヒントが段階的に出ること、クリア画面から確実に初期状態へ戻ること。
- 全画面でロゴが表示され、文字のふりがなと十分なボタンサイズが保たれること。

## 前提

- 会社のアピールは、ロゴの常時表示と「猫社員のおねがいごと」という世界観で自然に行い、保護者向けの採用・サービス案内は初回版の対象外とする。
- 漢字はJIS第1水準（2,965文字）までは使用して、全ての漢字のふりがなを振る。
- 「ねこ社員」はむやみに漢字にせず、このまま表記する。
- ねこ社員の発言（speech idleクラス内）はすべてひらがなにする。
